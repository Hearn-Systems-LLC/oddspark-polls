## Story

As a Poll watcher,
I want the Tally to update by itself while the Poll is open,
so that I never reach for refresh and never trust stale numbers unknowingly.

## Acceptance Criteria

1. **Given** an open Tally in one browser and a Vote cast in another, **When** the Vote is accepted, **Then** the first viewer's counts update within a few seconds without a reload (FR-21), via conditional polling of one versioned result projection on a 3-second cadence, only while the page is visible (AD-10).
2. **Given** any command that changes a visible Poll representation, **When** it commits, **Then** it increments `representation_version` through the single shared-kernel helper (de-risk rule #2), and the response validator combines that version with effective open/closed state so crossing a Deadline invalidates caches without a scheduled write (AD-24).
3. **Given** a viewer not entitled to the Tally (After Close before close, Creator-Only for non-creators), **When** they request the refresh/version endpoint, **Then** it applies the same `ViewerContext` authorization as the full result query and returns no version signal at all — vote-arrival timing and volume never leak through a ticking validator (AR-17).
4. **Given** a hidden tab, **When** the viewer returns (or network connectivity returns), **Then** polling resumes with an immediate refresh and the display snaps to current values without replaying missed changes.
5. **Given** a failed refresh, **When** it first occurs, **Then** the live indicator is replaced in place by `Not receiving updates. The counts shown are from {time}.` (label-caps-lg, text color), the last known Tally is preserved, retries back off up to 30 seconds, and reconnection restores the indicator and announces `Updates resumed.` once on the polite live region (UX-DR15/17).
6. **Given** an open Poll, **When** its Tally is on screen, **Then** the 6px gold live dot pulses beside `LIVE`, and when the Poll closes, polling stops and the indicator is replaced by `CLOSED`.

### Architecture Guardrails

- AD-24 verbatim rule: one monotonic `representation_version` per Poll, incremented in the same transaction as ANY change altering a public or authorized representation (Vote acceptance, Meeting revision, Comment moderation, manual close, result-visibility change, pre-Vote option/type edits); the response validator combines that version with effective open/closed state so a Deadline crossing invalidates without a scheduled write. A version-only validator is the exact bug this decision exists to kill [Source: `ARCHITECTURE-SPINE.md:355-366`; `reviews/review-adversarial.md:56-64,304-321`]
- De-risk rule #2 is ALREADY SATISFIED: `incrementRepresentationVersion` in `src/shared/application/index.ts:26-44` is the single helper (adapter SQL at `src/adapters/d1/index.ts:281-287`, appended to the vote batch); `CreatePoll` initializes to 1. No current command hand-rolls an increment and none is missing — 1.9 consumes the version; 1.12 will add close/edit/delete increments through the same helper [Source: `epics.md:157`; `1-5-cast-a-vote-that-counts-exactly-once.md:49`]
- AR-17/AD-21: authorization precedes projection AND caching. `private, no-store` is mandated for creator-only/not-yet-visible; entitled results must merely never enter a SHARED cache. This story keeps the blanket `private, no-store` everywhere and does conditional revalidation purely via `If-None-Match` held in client JS memory — no cache entry needed for a 304 [Source: `ARCHITECTURE-SPINE.md:318-328,380`; `reviews/review-adversarial.md:152-175` (C-2)]
- The no-version-signal AC is absolute for unentitled viewers: no ETag, no Last-Modified, no body version, no response field whose value, shape, or size varies with vote arrival. Hidden pages already publicly distinguish "hidden" from 404, so 204-vs-404 leaks nothing new [Source: `epics.md:473-475`]
- Layering (AD-1/AD-19/AD-23): the version QUERY belongs to `results` (which owns no facts); the endpoint is a thin inbound adapter; D1 implements ports; `shared/domain` owns `effectivePollStatus` (`src/shared/domain/index.ts:40-51`); closure is derived at read time, never stored (AD-11 — `db/migrations/0004_polls.sql:1-5`) [Source: `ARCHITECTURE-SPINE.md:46-54,194-201,290-301,342-353`]
- AD-9/AR-7: the live path reuses the SAME SQL tally projection as the page render — never a second projection and never a JS fold over Vote rows [Source: `ARCHITECTURE-SPINE.md:169-178`]
- Routing: the endpoint nests under the already-reserved per-Poll `results` sub-path — no reserved-slug registry change. Canonical URLs never change [Source: `ARCHITECTURE-SPINE.md:219-230`; `src/modules/polls/reserved-slugs.ts:5-27`]
