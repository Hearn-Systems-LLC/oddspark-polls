## Successes and strengths

1. **Multi-factor delivery system worked.** Justin attributed smooth assembly to sequencing, specs, adversarial review, tooling/AI workflow, *and* story quality together — not a single hero factor. Treat that combination as the keep-list for later epics.

2. **Architecture spine held under load.** Hexagonal modules (AD-1), the AD-7 vote transaction (idempotency, claims, representation_version), secret-keyed digests (AD-8), effective-state deadlines (AD-11), CSRF middleware (AD-22), and auth-before-projection results (AR-17) remained the decision language in story records and reviews.

3. **Vertical slices stacked.** Real paths shipped incrementally: `/sign-in` → `/creator/new` → `/{ref}` → results → lifecycle → share. Later stories (1.6–1.7, 1.9–1.11, 1.13) carried lighter review load once patterns existed.

4. **Handoffs closed inside the epic.** Multi-select bounds lock (1.7→1.12), overlay real consumer (1.1→1.12), option-FK race mapping (1.5→1.12), and submit-restore fixes were resolved rather than left as permanent TODOs.

5. **Deploy gate matured.** Migration immutability, unit + workerd integration + Playwright e2e in CI, staging smoke against real design tokens, binding-type drift check. Main deploys with proof.

6. **Progressive enhancement as a hard floor.** No-JS create/vote/delete paths, POST→303, ballot preservation under failure states.

7. **Story files as institutional memory.** Decisions tables, completion notes, exact AC copy, and deferred-work ledger kept continuity across agent sessions.

---

## Challenges and growth areas

1. **Capability-complete, narrative-incomplete (front door).** Production `/` remained a foundation/component gallery with the deploy smoke marker. Product loop lives on deep paths. Justin clarified this was a **path-discovery** need, not a mandate to rebuild landing before Epic 3. Resolved in retro by enumerating active paths (below).

2. **Review volume front-loaded.** Stories 1.1, 1.2, 1.3, 1.5, and 1.12 absorbed multi-round / multi-chunk adversarial review. Cost of establishing invariants; later velocity improved.

3. **`.astro` type blind spot.** `tsc --noEmit` skips templates; defects such as button primitives dropping `name`/`value` (killing form wiring and enhancers) only surface via review or e2e. `@astrojs/check` blocked on pinned TS 7 support.

4. **Deferred-work ledger growth.** Open items include public-surface caching policy, auth rate-limit / secondaryStorage, smoke version-propagation races, multi-select summary pluralization, create-form transient bound clamp, structural-seed doc drift. None blocked Epic 1 completion; several touch Epic 2 vote path or ops.

5. **Test harness friction.** Shared local D1 e2e serialization, auth-secret skip vs hard fail, cleanup lifecycle, smoke retry windows on brand-new routes.

---

## Key insights and learnings

1. **Keep the multi-factor system:** spine + story specs that name ports + adversarial multi-layer review + deploy gate + agent discipline (AGENTS.md). Dropping any leg reintroduces "lucky" delivery.

2. **Demoability ≠ story-done.** A closed FR map can still feel invisible if the default URL is a lab. For dogfood, document active paths; full landing remains Epic 3 (3.4/3.5).

3. **Foundation stories buy cheap later stories.** Pattern establishment (create form, vote transaction, results envelope, primitives) paid off as review load dropped mid-epic.

4. **Deferred ledger is a feature when used honestly.** Explicit defer + owner/story handoff beat silent TODOs; several deferred items were marked resolved mid-epic when the owning story landed.

5. **No significant Epic 2 plan break.** Epic 2 (toggles, IP checks, CAPTCHA, trust badge) still correctly mounts on Epic 1's claims schema, digests, Session Checks default, and vote surfaces.
