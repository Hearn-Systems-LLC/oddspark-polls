## Successes and strengths

1. **AD-7 vote transaction held under extension.** 2.2 added IP claims to the existing batch, 2.3 inserted CAPTCHA verification before it, 2.4 read toggle state from its projections. Not one story reshaped the transaction — they all extended around a stable core.

2. **Secrets discipline matured.** 2.3's Turnstile provisioning established the pattern: `secrets.required` in `wrangler.jsonc` as binding/type/deploy truth, masked rotation via `provision-auth-secrets.zsh`, staging widget registration before merge. Never a real credential in Git, chat, or CI.

3. **Architecture vocabulary governed all four stories.** AD-7, AD-8, AD-19, AD-23 served as decision language in every story record. Twenty-six binding decisions (D1-D13 across stories) were resolved at story creation before code landed.

4. **Review findings decreased in severity across the epic.** 2.1 had a HIGH finding (failed persistence rendering rejected draft as truth). 2.4's findings were presentation-level (a11y `role="list"`, duplication, regex scoping). The quality floor rose as team absorbed Epic 1's conventions.

5. **Stories stacked with zero regression rework.** Each story built cleanly on the prior: 2.1 established toggle storage and locking, 2.2 added IP digests to the claims table, 2.3 activated CAPTCHA with a new outbound adapter, 2.4 read toggle state to render the trust badge. No mid-epic architecture churn.

6. **Deploy gate held.** Every story passed `migrations:guard → test → check → test:e2e → types → binding-drift → build:production` before merge.

7. **One story = one branch = one PR = adversarial review.** The Epic 1 pattern continued unchanged.

## Challenges and growth areas

1. **Story 2.3 was the costliest story.** New binding (Turnstile), new secrets (`TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY`), new deployment config (`scripts/deploy-config.mjs`), staging deployment for real widget verification. Eight config files and five test files touched. This is the cost of a new outbound adapter with real provider dependencies.

2. **Astro scoping bit us twice.** 2.4's review found `.results-tally-badge { margin-top }` in `results-tally.astro` couldn't reach child component DOM — needed `:global()`. Same class of issue as 2.1's finding about render-order and CSS specificity.

3. **E2E environment complexity scaled with feature count.** Every spec needs auth setup (`seedCreatorSession`), D1 seeding, cleanup, and distinct cookie jars. 2.2's IP spec required controlled Cloudflare headers (`CF-Connecting-IP`). 2.3 needed real Turnstile tokens and a visual-only force-interactive key. The shared E2E harness is functional but verbose.

4. **Deferred-work accumulated.** Three new items from 2.4 review: SQL injection pattern in `seedPoll` (pre-existing E2E convention), walker test fragility (pre-existing), and `afterAll` cleanup silent leaks (pre-existing, every E2E spec).

5. **`.astro` type blind spot persists.** `tsc --noEmit` still skips templates. `@astrojs/check` remains blocked on pinned TS 7. Component wiring defects only surface via review or e2e.

## Key insights and learnings

1. **The AD-7 transaction is the project's load-bearing joint.** Every Epic 2 story touched or read it; none reshaped it. The decision to build the full transaction shape in Epic 1 (Story 1.5) with claims schema, representation_version, and submission_id idempotency was correct.

2. **Secrets management must be visible.** 2.3's approach — declare every required secret name in `wrangler.jsonc` at every environment level, let Wrangler enforce presence, let health/smoke catch missing runtime values — makes provisioning auditable without exposing values.

3. **Computed-style E2E assertions are worth the cost.** 2.1's review established that DOM-presence assertions are vacuous for styling contracts. 2.4 baked computed-style checks (`font-size: 12px`, `color`, `border-top`) into the E2E suite from day one, and it caught the Astro scoping issue on the `/results` surface.

4. **Internal duplicate of `PollSecurityToggles` mapping is the kind of defect adversarial review catches.** 2.4 review flagged the identical mapping at `[reference].astro` and `d1/index.ts`. A `makeSecurityToggles` constructor in shared domain fixed it. The extra abstraction is small; the compile-time safety is real.

5. **Deferred ledger is a feature when used honestly.** Three items deferred from 2.4 review were explicitly tagged pre-existing. None block Epic 3. The ledger makes triage visible rather than letting TODOs rot silently.
