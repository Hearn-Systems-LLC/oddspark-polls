### Stories delivered

1. **3-1 — Listing control: opt into discovery**: Single-select chooser at creation (`Unlisted` default / `Listed`), persistent `listing_state`, `listing-badge` component on creator card/detail.
2. **3-2 — Discover catalog & sitemap**: `/discover` public catalog, pagination, `sitemap.xml`, `robots.txt`, and `private, no-store` caching boundary.
3. **3-3 — Administrator delisting**: Single out-of-band Administrator can delist/re-list polls; read-only creator explanation; link-based voting remains uninterrupted.
4. **3-4 — Landing page**: Product landing page at `/` with plain-language statement, technical build account, public repository entry, and smoke marker.
5. **3-5 — Demo Poll**: Live embedded Demo Poll on landing page, CAPTCHA integration, live Tally, atomic aggregate replacement reset adapter for owner reset.
6. **3-6 — Presentable repository**: Evaluator-first `README.md`, centralized `public-repository-link.astro` footer, architecture spine integration, value-redacted all-history Gitleaks audit, and full local gate.

## Successes and strengths

1. **Hexagonal Modular Monolith (AD-1) simplified public features.** Adding `/discover`, Administrator moderation, and Demo Poll reset required no microservice overhead or domain refactored chaos. Domain logic in `src/modules/*` remained decoupled from Astro routes.
2. **Server-rendered progressive enhancement (AD-2) kept public surfaces fast and accessible.** Landing, Discovery, voting, and Results load instantly without client-side framework hydration. JavaScript enhances live polling and CAPTCHA without breaking baseline HTML navigation.
3. **Responsive desktop + mobile viewport contracts strictly maintained.** Desktop viewports (1280px+) leverage 2-column grid arrangements for post-vote and Results viewports, wider measure bounds, and 32px desktop margins (`--space-margin-desktop`).
4. **Clean security history audit discipline.** Established reproducible, value-redacted Gitleaks audit procedures covering 91 reachable commits without committing candidate secrets, scanner dumps, or raw reports.
5. **100% follow-through on Epic 2 retrospective action items.** All 5 previous action items (README active path map, sprint-status tracking, deferred-work triage, and delivery gate discipline) were fully satisfied in Epic 3.

---

## Challenges and growth areas

1. **Astro template static type checking remains a blind spot.** `tsc --noEmit` skips `.astro` templates; `@astrojs/check` remains blocked on TypeScript 7 compatibility. Component prop and seam contracts must be verified via unit source tests and E2E browser tests.
2. **CI pipeline execution time.** Running full Vitest integration suites alongside Playwright Chromium E2E tests in workerd takes ~20 minutes in GitHub Actions.
3. **Gitleaks false positive management.** Immutable historical commit manifest entries required exact fingerprinting in `.gitleaksignore`.
