## Epic summary

**Epic 5: Ranked-Choice Polls**  
Communities can run trustworthy ranked-choice polls whose ballots are quick and accessible to cast, whose instant-runoff outcome is deterministic, and whose completed count is independently verifiable. The epic exposes enough round and ballot evidence for a skeptical reader to reproduce the result rather than merely trust an asserted winner.

## Successes and strengths

1. **Architectural purity of the IRV Tabulator (AD-9/AR-7).** The pure `tabulate-irv.ts` module has zero provider imports, zero D1/Astro coupling, and zero randomness. It is shared across live results, closed views, post-vote views, exports, and tests, validated by fast-check property tests.
2. **First-class strategy port extension (AD-3).** Ranked Choice fully implemented `create`, `validateSubmission`, `persistFacts`, `projectResults`, and `projectExport` without changing `POLL_TYPE_CONTRACT_VERSION` or modifying the format-neutral CSV/XLSX export routes.
3. **Complete verification transparency.** The round-table display and closed Ballot Manifest (`/{link}/manifest`) fulfill the product promise: the winner is mathematically recomputable by any reader rather than asserted on trust alone.
4. **Disciplined Code Review & Chunked Triage.** Story 5.2 was reviewed in 3 structured group chunks (pure tabulator, wiring, UI/live) and 5.3 underwent adversarial multi-layer code review, surfacing and resolving edge cases (e.g. manifest canonical row collapsing, comment validation, snapshot version coherence) before merge.
5. **Flawless Epic 4 Follow-through.** Every critical action item (C1–C4) and process improvement (P1–P4, T1–T3) from the Epic 4 retrospective was satisfied during Epic 5 execution.

## Challenges and growth areas

1. **Manifest scalability for large Polls.** The current Ballot Manifest loads all normalized preferences into memory and renders an unpaginated list (`completeness over comfort`). While correct for casual polls, a 50k-ballot poll could strain Worker memory. Deferred for monitoring (DW-532).
2. **Review chunking discipline for multi-layer features.** Story 5.2's initial attempt tried to review pure tabulator logic alongside UI wiring before the suite loaded. Chunking the review into discrete layers (Group 1: core logic, Group 2: adapters/wiring, Group 3: UI/live) proved necessary for clear triage.
3. **Complex state matrix on live enhancers.** Live-updating the round table and comments required careful shape validation (`isCountRow`, `isRound`, `isCommentView`) to prevent DOM injection and reload loops.

---

## Key insights and learnings

1. **Domain pure-core isolation pays massive dividends:** Keeping `tabulate-irv.ts` free of framework dependencies allowed 26 property-based unit tests to run in milliseconds and guaranteed 100% parity across server HTML, live polling, and exports.
2. **Canonical data representations must collapse identical rows:** Sorting ballots by position sequence and collapsing identical ballots into `{ rankings, count }` rows made the Ballot Manifest deterministic and independent of database insertion order.
3. **Export projection ports keep delivery routes clean:** Implementing `RankedChoiceExportFacts` on the strategy port allowed CSV and XLSX downloads to work out-of-the-box using the existing export controllers.
